## 事件契约(前后端必须一致)

**事件 payload**(Rust 侧结构体统一 `#[serde(rename_all = "camelCase")]`):
- `agent-output`:`{ runId: number, stream: "stdout" | "stderr", line: string }`
- `agent-exit`:`{ runId: number, code: number | null, killed: boolean }`
  - `killed = true`:用户主动终止(灰色"已终止");`false` 时按 `code == 0` 区分成功(绿)/失败(红)

**runId 由前端生成**:点启动时 `runId = Date.now()` 写入 ref 后再 invoke;Rust 直接使用传入值,不自增分配。

**命令**(**错误一律返回结构化 `CmdError`,不用裸字符串**——前端需要按类型分支,不能靠匹配错误文案):
```rust
#[derive(Serialize)] #[serde(rename_all = "camelCase")]
struct CmdError { kind: String, message: String }
// kind 取值:"alreadyRunning" | "spawnFailed" | "killFailed" | "noProcess" | "unknownPreset"
```
- `spawn_test_agent(preset: string, runId: number) -> Result<(), CmdError>`
  - preset:`"node"` / `"ping"` / `"node-fast-exit"`
  - 槽位占用 → `kind="alreadyRunning"`;**spawn 本身失败(如 node 不在 PATH)→ `kind="spawnFailed"`**
  - 这两个 kind 前端处理方式**完全不同**(见下)
- `kill_test_agent() -> Result<(), CmdError>`
- `get_agent_status() -> Result<{ running: bool, runId: number | null }, CmdError>` — 只恢复运行标志与 runId,不恢复历史输出

## 关键逻辑

### 1. 前端状态机(`src/App.tsx`)

**唯一状态 `phase`**(按钮可用性、事件接受条件、runId 生命周期全部由它派生):

| phase | 含义 | 启动 | 终止 | 重试按钮 | 圆点 |
|---|---|---|---|---|---|
| `subscribing` | 事件监听尚未注册成功 | 禁用 | 禁用 | **不显示** | 灰 |
| `unknown` | 监听已就绪,但状态查询失败/前后端脱节 | 禁用 | 禁用 | 显示 | 灰 |
| `idle` | 空闲 | 可用 | 禁用 | — | 灰 |
| `starting` | 已 invoke,未确认 | 禁用 | 禁用 | — | 蓝(呼吸) |
| `running` | 运行中 | **禁用** | 可用 | — | 蓝(呼吸) |
| `terminating` | 已请求终止,等退出事件 | 禁用 | 禁用 | — | 蓝→灰过渡 |
| `finished` | 已结束(绿/红/灰由退出事件定) | 可用 | 禁用 | — | 绿/红/灰 |

> **为什么必须把 `subscribing` 与 `unknown` 分开**:两者的恢复方式根本不同。`subscribing` 时监听器还不存在,给"重新同步"按钮是假的安全感——用户点它可能拿到 `running`,随后进程的输出与退出事件无人接收。只有监听确认上线后(进入 `unknown`),重试才是有效的。

**挂载代际编号(替代 v6 的 disposedRef)——修复 StrictMode 竞态**

v6 用一个共享布尔 `disposedRef` 并在 effect 开头重置为 `false`;而 StrictMode 是"挂载 → 清理 → 再挂载",第一轮挂载尚未完成的 `listen()` 回调会在第二轮重置后读到 `false`,误以为仍有效 → 第一套监听器残留、事件被处理两次。改为**每轮挂载一个自增编号**,清理时递增即可作废该轮全部在途回调,**不需要任何"重置"**:

```tsx
const mountGenRef = useRef(0);
const alive = (gen: number) => mountGenRef.current === gen;   // 代际未变 = 仍属本次挂载

useEffect(() => {
  const gen = ++mountGenRef.current;      // 本次挂载的唯一编号
  Promise.all([
    listen<OutputEvent>("agent-output", e => {
      if (e.payload.runId !== runIdRef.current) return;
      appendLine(e.payload);
    }),
    listen<ExitEvent>("agent-exit", e => {
      if (e.payload.runId !== runIdRef.current) {
        // 状态未知期 runId 尚不可知(刷新恢复 / 前后端脱节):接受并按退出推进,避免永久卡"运行中"
        if (phaseRef.current === "unknown" || phaseRef.current === "subscribing") {
          runIdRef.current = e.payload.runId; applyExit(e.payload);
        }
        return;
      }
      applyExit(e.payload);
    }),
  ]).then(fns => {
    if (!alive(gen)) { fns.forEach(f => f()); return; }   // 本轮挂载已作废 → 立即全部 unlisten
    unlistenRef.current = fns;
    syncStatus(gen);          // 监听确认上线后才查状态(先查会丢失两者之间的退出事件)
  }).catch(() => {
    if (!alive(gen)) return;
    setPhase("subscribing");  // 停在订阅失败:启动保持禁用,且不显示重试(监听不在,重试无意义)
    setError("事件订阅失败,请重启应用");
  });
  return () => {
    mountGenRef.current++;    // 递增即作废本次挂载的所有在途回调(卸载与 StrictMode 首轮清理都靠它)
    unlistenRef.current?.forEach(f => f());
    unlistenRef.current = null;
  };
}, []);
```

**操作令牌(opRef)** —— 所有异步结果必须验号才允许写 phase:

```tsx
const opRef = useRef(0);
const beginOp = () => ++opRef.current;
const opValid = (t: number) => opRef.current === t;
```
1. 发起异步操作(start / kill / syncStatus)时取号
2. 结果返回后 `if (!opValid(token)) return;`
3. **`applyExit()` 内部递增 `opRef`** —— 退出事件是状态的最终权威,一到就作废所有在途操作

```tsx
function applyExit(p: ExitEvent) {
  if (phaseRef.current === "finished") return;   // 重复退出事件幂等丢弃
  opRef.current++;                               // 作废在途的 start/kill/同步
  setPhase("finished");
  setResult(p.killed ? "terminated" : p.code === 0 ? "success" : "failed");
}
```

**`syncStatus(gen)`**
```tsx
function syncStatus(gen: number) {
  const token = beginOp();
  invoke<{ running: boolean; runId: number | null }>("get_agent_status").then(s => {
    if (!alive(gen) || !opValid(token)) return;    // 已卸载/已重挂载,或期间有退出事件 → 丢弃
    if (phaseRef.current !== "unknown" && phaseRef.current !== "subscribing") return;  // 已被推进 → 快照过期
    if (s.running) { runIdRef.current = s.runId; setPhase("running"); }
    else setPhase("idle");
  }).catch(err => {
    if (!alive(gen) || !opValid(token)) return;
    setPhase("unknown");                            // 保持"状态未知":启动禁用 + 显示重新同步
    setError("无法读取后端状态:" + err);
  });
}
```
> **为什么状态未知时不落 idle**:若后端其实仍在运行,落 idle 会让启动按钮可用 → 用户点击被后端拒绝 → 旧进程的输出与退出事件再也无法匹配(彻底失联)。

**`start(preset)` — 函数内门禁 + 令牌校验 + 按 kind 分支**
```tsx
async function start(preset: string) {
  // 按钮 disabled 依赖重渲染,快速双击/自动化点击可能抢在重渲染之前,函数内必须再判一次
  if (phaseRef.current !== "idle" && phaseRef.current !== "finished") return;
  const token = beginOp();
  const gen = mountGenRef.current;
  const id = Date.now();
  runIdRef.current = id;                    // 先写 ref 再 invoke,第一条输出事件才有匹配基准
  setOutputs([]); setError(null); setPhase("starting");
  try {
    await invoke("spawn_test_agent", { preset, runId: id });
    if (!alive(gen) || !opValid(token)) return;   // 期间进程已退出并发 agent-exit → 不覆盖 finished
    setPhase("running");
  } catch (e) {
    if (!alive(gen) || !opValid(token)) return;
    if (errKind(e) === "alreadyRunning") {
      // 后端说已有进程在跑 = 前后端状态已脱节。此时绝不能清空 runIdRef / 落 idle,
      // 否则那个真实进程的输出与退出事件会因编号不匹配而永远收不到 → 转入状态未知并重新同步
      setError("检测到后台仍有进程运行,正在重新同步…");
      setPhase("unknown");
      syncStatus(mountGenRef.current);
      return;
    }
    runIdRef.current = null;                // 普通启动失败(spawnFailed):此刻确无存活运行,清空安全
    setPhase("idle"); setError(String(errMessage(e)));
  }
}
```

**`kill()`**
```tsx
async function kill() {
  if (phaseRef.current !== "running") return;   // 函数内门禁
  const token = beginOp();
  const gen = mountGenRef.current;
  setPhase("terminating");
  try { await invoke("kill_test_agent"); }      // 成功不做别的:等 agent-exit 推进到 finished
  catch (e) {
    if (!alive(gen) || !opValid(token)) return; // 进程其实已自行退出、退出事件已到 → 保持 finished
    setPhase("running"); setError(String(errMessage(e)));
  }
}
```

**`setPhase` 统一封装**(同时写 state 与 `phaseRef`,异步回调一律读 `phaseRef`):
```tsx
function setPhase(p: Phase) { phaseRef.current = p; setPhaseState(p); }
```
`errKind(e)` / `errMessage(e)`:Tauri invoke 抛出的错误即 Rust `CmdError` 反序列化结果,直接取 `e.kind` / `e.message`。

### 2. Rust(`src-tauri/src/lib.rs`)

**状态结构**
```rust
struct AgentState { slot: Mutex<Option<RunInfo>> }   // Some = 运行中
struct RunInfo { child: Child, killed: Arc<AtomicBool>, run_id: u64 }  // runId 用 u64(前端 Date.now() 超 u32)
```

**`spawn_test_agent(preset, run_id)` — 全程单次持锁,消除双启动竞争**
- 锁定 `slot` 不中途释放,直到:检查 `is_some()`(是 → `CmdError{kind:"alreadyRunning"}`)→ 依 preset 构造命令 → spawn(`Err` → `kind:"spawnFailed"`,附原始错误)→ 取走 stdout/stderr 句柄 → `slot.replace(RunInfo)` → 生成 3 线程 → 释放锁
- preset 映射:
  - `node` → `node <脚本绝对路径>`
  - `node-fast-exit` → `node <脚本绝对路径> --fast-exit`
  - `ping` → `ping 127.0.0.1 -n 20`
  - 脚本路径解析:`app.path().resource_dir()?.join("scripts/test-agent.js")`,不存在则回退 `env!("CARGO_MANIFEST_DIR")/../scripts/test-agent.js`(开发模式)
- Windows:`#[cfg(windows)]` + `StdCommandExt::creation_flags(0x08000000)`(CREATE_NO_WINDOW)
- stdout/stderr `piped`,stdin `Stdio::null()`
- 预留注释:孙进程清理需 Windows Job Object,阶段2 实现

**stdout/stderr 读线程(各一条)**
- `BufReader::read_until(b'\n')` 循环(不用 `lines()`,避免非法字节中断整条流)
- 解码:先 `std::str::from_utf8(bytes)`,失败再 `encoding_rs::GBK.decode(bytes)`(中文 Windows ping 输出是 GBK)。**不能**先 `from_utf8_lossy` 再检测——非法字节已被替换,无法判断原始编码
- 每行 `app.emit("agent-output", { runId, stream, line })`
- 进程退出 → 管道 EOF → 读线程自然结束,`JoinHandle` 交给监视线程

**监视线程 — 输出全部先于退出事件,状态及时释放**
- 每 200ms 锁内 `child.try_wait()`,拿到 `ExitStatus` 后按序:
  1. `let _ = stdout_handle.join(); let _ = stderr_handle.join();` — **无论 join 成败(含读线程 panic)都继续**;正常时管道已 EOF、join 快速返回;异常时最坏丢尾部输出,但状态必须释放,否则永久卡"已有进程运行"
  2. 锁内清空 `slot`(比对 run_id 再清,防御性)——**先清槽、后发事件**,前端收到退出事件立刻再启动时不会撞上虚假的"已有进程运行中"
  3. emit `agent-exit { runId, code, killed }`
- 轮询而非阻塞 `wait()`:child 留在 slot 供 kill 使用,所有权不能移交

**`kill_test_agent()` — 幂等 + 已退出判定**
- 锁内分四种情况:
  - 槽位为空(未启动/已结束)→ `Ok(())`,视为"无需终止"
  - `killed` 已为 true(终止处理中)→ `Ok(())`,不重复 store
  - 首次终止:`killed.store(true)` → `match child.kill()`
  - **`kill()` 返回 Err 时先 `child.try_wait()` 确认真实状态**(进程可能刚好在自然退出、监视线程尚未收尸的窗口内):
    - `Ok(Some(_))` → 进程**已自行结束** → `killed.store(false)`,返回 `Ok(())`,由监视线程发 `killed=false` 的正常退出事件(界面显示绿"已完成",而非红色失败)
    - 其余(`Ok(None)` 仍存活但杀不掉 / `Err`)→ `killed.store(false)` 回滚 + `CmdError{kind:"killFailed"}`
- 不取走 child、不发退出事件——退出事件统一由监视线程发(单一出口)

**`RunEvent::Exit` 清理**
- `Builder::build(...).run(|app, event| ...)` 中匹配 `RunEvent::Exit`:锁内对残留 child `kill()`,忽略错误;退出瞬间 emit 失败忽略

**Tauri v2 API 要点**
- `use tauri::Emitter;` 后 `app.emit()` 可从任意线程调用(AppHandle Send+Sync)
- 自定义命令 invoke 无需额外权限;`capabilities/default.json` 已含 `core:default`(覆盖 event listen),保留勿删
- `CmdError` 需 `Serialize`;命令签名 `Result<T, CmdError>`,前端 catch 到的即该对象

## 验收(对照任务书 + 六轮评审)

- 两个正式预设输出均实时滚动,stderr 行区分色可见,**最后几行一定出现在状态变化之前**
- 页面加载后启动按钮短暂禁用→可用;就绪后启动 Ping 预设,**第一行不缺失**
- **运行中启动按钮为禁用态**;快速双击启动只会有一个进程,状态正常
- 点击终止:立即停止,灰色"已终止";**连续快速点击终止两次:最终仍是灰色"已终止",不出现红色失败**
- **选"Node 快速退出"预设启动:进程打印一行即退出,界面必须落到"已完成"(绿),不得卡在"运行中"或"启动中"**(令牌校验 + 秒退竞态的验证点;此前该场景无法手工复现,故增设该预设)
- 进程自然结束后立刻点终止:不出现红色失败(命中收尸窗口时按"已自行结束"处理,显示绿"已完成";该窗口难以精确手工触发,以代码评审确认判定逻辑为主)
- 进程自然结束后立刻再点启动:不应出现虚假的"已有进程运行中"
- 运行中刷新页面:恢复"运行中",输出区为空(预期);刷新后**什么都不做等其自然结束:圆点必须变为绿/灰,不能永久卡"运行中"**
- **开发模式下控制台无 React 警告、输出不重复**(StrictMode 双挂载的验证点:同一条输出若出现两次即为监听器残留)
- 启动失败(临时把预设命令名改错验证):红字 + 回到空闲可再次启动
- 输出区上滚出现「回到最新」;系统深色模式下输出区/边框/状态色均无亮白断层;900×600 无横向溢出
- 关闭窗口后任务管理器无 node/ping 残留

## 风险与对策

| 风险 | 对策 |
|---|---|
| ping 中文输出乱码(GBK) | `from_utf8` 失败 → `encoding_rs::GBK` 解码 |
| 旧进程输出混入新任务 | 事件携带前端生成的 runId,ref 过滤 |
| 启动期丢首行输出 | runId 预生成 + phase 门控(订阅期禁用启动) |
| 迟到异步结果覆盖新状态 | 操作令牌:结果返回先验号,退出事件递增令牌作废在途操作 |
| StrictMode 双挂载导致监听残留/双份输出 | 挂载代际编号:清理时递增即作废该轮在途回调,不做重置 |
| 订阅失败与状态未知混淆 | 拆为 `subscribing` / `unknown` 两阶段,仅后者显示重试 |
| 后端报"已有进程"时前端失联 | 结构化错误按 kind 分支:`alreadyRunning` → 转入 `unknown` 并重新同步,不清空 runId |
| 无效 runId 覆盖有效 runId | 运行期启动按钮禁用 + 函数内门禁,该路径不可达 |
| 刷新恢复丢退出事件 / 迟到快照覆盖 | 状态未知期接受未知 runId 的退出事件 + 快照验号并判 phase |
| 状态查询失败后失联 | 停在 `unknown`(禁用启动)+ 红字 + 「重新同步」 |
| 退出后虚假"已有进程运行中" | 监视线程先清槽、后 emit |
| 读线程 panic 导致状态卡死 | join 失败不阻塞,槽位必然释放 |
| 重复终止把 killed 改回 false | 后端幂等 + phase=terminating 禁用按钮 |
| 收尸窗口内终止误报失败 | kill Err 后 try_wait 确认已退出 → 按正常结束处理 |
| 打包后脚本路径失效 | resources 映射写法 + resource_dir 解析 + dev 回退 |
| node 不在 PATH | spawnFailed 错误,界面红字"请确认已安装 Node.js" |
